# Scope to Demo

Turn the agreed problem into a demonstrable slice that fits the actual event clock.

1. Confirm the submission cutoff, deliverable, team constraints, and allowed tools/data.
2. Define the smallest workflow that proves the intended user outcome. Name the input, visible response, and result.
3. List the happy path, one likely failure, a tiny test set, and an observable measure.
4. Assign owners for problem/scope, build/integration, evidence/privacy, and demo/submission. Name backups for deadline-critical work.
5. Get a thin happy path running early; integrate often and keep a known-good build.
6. Agree what to cut if late. Reserve the last 60–90 minutes before the real deadline for checks, submission, and rehearsal when the schedule allows.

Do not add features just because time remains. Make limits visible, test on approved examples, and avoid unsupported impact claims. Use `templates/team-roles.md` and `templates/decision-log.md` when available.
