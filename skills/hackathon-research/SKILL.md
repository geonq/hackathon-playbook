# Hackathon Research

Build a short, decision-ready event brief from current sources.

1. Start with organizer and registration pages. Use official product docs only for setup facts.
2. Record the checked date and link every material claim to the page that supports it.
3. Label claims as **primary/confirmed**, **secondary**, **inference/recommendation**, or **unknown**. Never describe an inferred judging criterion as official.
4. Compare schedule, venue, attendance, track, prize, and policy details across sources. State conflicts plainly and choose a conservative working cutoff when deadlines disagree.
5. List unannounced items as questions for the organizer: team size, deliverables, pre-build policy, required tools, IP/data terms, rubric, and submission timing.
6. End with a brief preparation plan tied to confirmed constraints and label advice as advice.

If a source is unavailable, say so and do not fill the gap from memory. For the Berlin 2026 snapshots in this kit, consult `events/*/sources.md` and refresh them before use.
