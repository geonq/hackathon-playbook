# Demo and Submission Review

Review against the published event rules and the team's stated problem. Do not invent a judging rubric.

- Confirm the actual deadline, timezone, required fields, links, repository access, demo format, and rules on tools, data, or pre-built work.
- Start from a clean state and exercise the promised end-to-end path. Check one likely failure and prepare an allowed fallback.
- Verify that measured claims match observed tests; state sample size, failures, uncertainty, and what still needs a person.
- Check the repository and demo for credentials, personal or confidential data, unauthorized assets, and claims of partner approval that were not given.
- Confirm code release, license, donation, or handoff terms with the organizer and problem owner.
- Rehearse within the time limit. Verify every required link and capture submission receipt.

Use `templates/demo-script.md` and `templates/submission-checklist.md` when available. If there is no time for all checks, protect correctness, credential/data safety, and on-time submission first.
