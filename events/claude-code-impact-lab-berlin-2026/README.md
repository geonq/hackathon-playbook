## Preparation

Use the [event-day rules and idea strategy](../../docs/EVENT_DAY_STRATEGY.md) and fill the [competition plan](../../templates/competition-plan.md) before locking an idea. Confirm participant and team eligibility, allowed pre-event work, approved data and tools, required deliverables, and any code, publication, or handoff terms. An unresolved rule stays unresolved until the host confirms it.

Listen closely to the actual problem and the people who experience it. The event listing says the lab will work on themes and problems from the first Claude Conversation, but does not name the exact challenge or beneficiary. Do not arrive committed to a product idea.

At kickoff, learn who the problem owner is, what task is painful today, what data may be used, what must remain human-reviewed, and what the organizer expects to see. Write one narrow workflow and one observable measure before splitting into build tasks. A product/workflow lead can keep the user problem, scope, and demo story connected while pairing with builders.

Check Claude Code before the day: follow the [official setup guide](https://code.claude.com/docs/en/setup), then run `claude --version` and `claude doctor`. The event listing mentions Claude API credits but does not state the amount, access method, model availability, or whether attendees need a separate account. Confirm with the host; do not assume the event title alone makes a particular tool mandatory.

The listing does not state a pre-build policy. Keep setup to tool installation and account readiness only as far as the organizer permits; do not run event-specific API/model prompts, prepare project code, or stage project data/assets until the host confirms those actions are allowed. A harmless test is still an API experiment.

Use the [prep checklist](prep-checklist.md), [project brief](../../templates/project-brief.md), and [demo script](../../templates/demo-script.md). Build one complete user path early, test it on approved examples, and reserve the last 60–90 minutes allowed by the confirmed schedule for verification, rehearsal, and submission.

If also attending the Nebius event the next day, keep the projects and materials separate. Reuse Saturday code, data, prompts, assets, or a project on Sunday only if both events' rules or organizers explicitly permit it; disclose reuse when required.

## Ask the host or problem owner

- What is the actual problem statement, partner, and intended user?
- What are the deliverables, demo slot, and submission cutoff?
- Which pre-event setup, API/model experiments, code, prompts, data, and assets are permitted? Is there a required tool or repository format?
- What data may be used, and what privacy or security constraints apply?
- Who owns the code after the event? What license, donation, publication, or handoff terms apply?
- What does “top builds shared with Anthropic” mean for code, data, and participant information?
- How are Claude API credits issued, and what happens if access or quota fails?
