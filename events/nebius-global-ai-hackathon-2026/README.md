# Nebius x NVIDIA Global AI Hackathon · Online · 2026

**Checked against official pages on 15 October 2026.** This is a separate Devpost contest. Its rules do not establish the rules, judging, or award overlap for the local Nebius Build Week Hackathon in Berlin on 18 October. Recheck the [Devpost overview](https://nebiusglobalaihackathon.devpost.com/) and [official rules](https://nebiusglobalaihackathon.devpost.com/rules) before registering or submitting.

## Separate entry and deadline

The Global Hackathon is online and has its own submission form. Join it through the [Devpost page](https://nebiusglobalaihackathon.devpost.com/) using a Devpost account; attending the Berlin Build Week event does not itself register a project. The listed submission deadline is **October 30, 2026 at 10:00am PDT**. Keep that timezone as published and check Devpost for updates.

The Global project must be working software that makes a runtime call to Nebius Token Factory **or** runs on Nebius AI Cloud compute, and uses at least one NVIDIA open-source model. The [official rules define the platform requirement and eligible compute examples](https://nebiusglobalaihackathon.devpost.com/rules). A local event demo, an installed tool, or a model mentioned in a README does not by itself satisfy these runtime requirements.

## Global tracks

Choose the single best-fitting track on the Devpost submission:

- **Coding and Agentic Engineering:** coding agents and developer tools that write, run, and test code.
- **Best Apps and Agents:** a useful app or agent, from a productivity tool or copilot to an automated workflow.
- **Personal AI:** an assistant with user-controlled data, memory, tools, and recurring tasks.
- **Physical AI:** embodied or edge agents, such as robotics, IoT, or on-device intelligence.

These are the Global Devpost tracks. They are separate from the Berlin event's Cloud & Serverless, Apps & Agentic AI, and Vertical AI tracks. Check the complete chosen-track description before committing: Coding and Agentic Engineering specifically describes agents that write, run, and test code in Token Factory; Best Apps and Agents describes powering the app with Nemotron through Token Factory; Personal AI calls for at least one NVIDIA open-source model; Physical AI describes embodied/edge systems and its own hardware-demo provisions. Track-specific tools and submission conditions may be narrower than the Global-wide minimum.

## Submission materials

The rules require a working project and track, project description, working demo/hosted app/test-build URL (the demo URL exception is for Physical AI), public code repository, short public YouTube demo, and feedback on the Nebius/NVIDIA tools and models used. For a public repository, include all necessary source and assets, an open-source license visible on the repo, and a README with setup and run instructions. The video must be **under three minutes**, show the project functioning, and be public on YouTube. Physical AI videos have the additional one-minute operating-hardware footage requirement (or key modules in action if the project has no physical hardware). The [Devpost rules](https://nebiusglobalaihackathon.devpost.com/rules) are controlling for details; judges are not required to test the project and may judge from the submission materials alone.

The current rules require the submitted project to be available free of charge and without restriction for judging and testing through the end of the judging period, currently listed as **December 15, 2026 at 12:00pm Pacific Time**. Assign someone to keep the demo and its dependencies running through that date, monitor credit/hosting expiry, and put any required test credentials in the submission's testing instructions rather than the public repository.

If the project existed before the Global Submission Period began on **August 26, 2026**, the submission must explain what was significantly updated during the Submission Period. Keep a short dated record of the work that is actually new. The separate global deadline and materials should be planned independently from the local Sunday submission.

## Global eligibility and judging

The official rules use a two-stage evaluation. **Stage one is pass/fail:** the project must reasonably fit its chosen track and genuinely apply the required platform/model technology. Submissions that pass are then judged on four equally weighted criteria: **Technological Implementation, Design, Potential Impact, and Quality of the Idea.** These criteria apply to the Global Devpost contest only; no local Berlin rubric was published on the event pages checked for this brief.

The Global rules list **$20,000, $10,000, and $6,000 Overall Awards**, a Jetson Orin Nano for each of four Track Awards, and a limit of **one Overall Award or one Track Award, plus one Bonus Award** per project. The listed bonuses include:

- **Best Use of Tavily:** $3,000; the project makes a functional runtime call to the Tavily API as part of its solution.
- **Most Valuable Feedback:** $100 and an NVIDIA swag pack; the entrant completes the feedback submission section, which is evaluated for completeness, viability, and potential impact.
- **City Winner:** $500; the entrant attended one of the named participating IRL Builders & Brews events, including Berlin.

Do not count on the bonus awards as guaranteed outcomes. Check the [official rules](https://nebiusglobalaihackathon.devpost.com/rules) for current categories and eligibility.

### Berlin City Winner is unresolved for the 18 October event

The [Global rules](https://nebiusglobalaihackathon.devpost.com/rules) list participating Builders & Brews city events and include Berlin. Nebius's [Builders & Brews event page](https://nebius.com/events/builders-and-brews) lists Berlin on **29 September**; the linked [Berlin Luma event](https://luma.com/kpdwf7ej) identifies w3.hub. The 18 October local event is separately listed as the **Nebius Build Week Hackathon** at Delta Campus + CODE University. The public sources checked do not say that attending the October 18 hackathon counts as attending the Berlin Builders & Brews event. Ask Devpost or Nebius for written confirmation before relying on Berlin City Winner eligibility.

## Local Sunday work and Global submission are separate

A project built on Sunday may be a candidate for a separate Devpost submission only if the local event's rules permit the work, ownership, data, public repository, and reuse. The local pages checked for the [Berlin event](../nebius-build-week-berlin-2026/README.md) do not publish its pre-build, code/IP, or data terms; those local rules remain unknown, and the separate Global submission window does not answer them. Resolve them with the local organizer before carrying local work into a public submission.

The Global rules also state that a project must not have been developed, or derived from a project developed, with financial or preferential support from the sponsor or administrator before the end of the Global Submission Period. **The public rules do not say whether any credits, mentoring, or other support from the separate October 18 local event trigger this clause.** Ask Nebius/Devpost for a written interpretation that addresses any event credits or support before using them in a Global entry; this brief does not assert that local support either does or does not affect eligibility.

Before publishing, confirm every contributor's rights to code, prompts, data, and assets; remove confidential or personal data and secrets; check third-party licenses and permission to use logos, screenshots, and music; and verify the exact Global fields and access terms. Local permission to demo is not automatically permission to release a public open-source repository. Use the separate [Global prep checklist](prep-checklist.md) to build the entry after the Sunday local submission is secure.
